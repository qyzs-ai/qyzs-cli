# QYZS MARKSCAN — 智能文档识别与结构化输出流水线 (SSOT)

本文档是 `qyzs markscan` 子命令行为契约的唯一事实源。
能力边界实测数据见 `capability_matrix.toml`；发布制度见 `docs/RELEASE.md`。

调度优先级固定为：**准确度 > 处理效率 > Token 消耗**。项目假定庆阳模型账户侧
没有调用额度限制；能力矩阵中的上下文、输出 Token 和视觉 Token 数值描述模型或部署
的技术边界，不是账户配额。不得为节省 Token 主动删减 rigor 的交叉验证通道。

## 1. 定位

一站式文档识别与结构化输出：输入本地文件或 http(s) URL，自动识别格式、路由抽取
通道、可选多轮交叉验证与 LLM 排版润色，经内部文档层确定性渲染为 Markdown、
HTML 或纯文本。

### 1.1 输出格式

- `--output-format md|html|txt`，默认 `md`，不指定时保持既有 Markdown 行为。
- `--concurrency 1~64` 控制整次任务共享的远程请求并行度（默认 4）；页面 OCR、VL、
  仲裁和复核均受同一个信号量约束，避免局部并发相乘失控。配置多个 API Key 时请求
  按轮询分流，单 Key 配置保持兼容。
- `md` 原样保留最终 Markdown，并默认附加 YAML front matter；`--no-front-matter`
  可关闭。
- `html` 生成完整 UTF-8 HTML 文档，保留标题、列表、表格、链接、代码块等结构。
- `txt` 去除 Markdown 标记但保留可读的段落、列表和表格单元格文本。
- 多文件/目录输入按格式使用 `.md`、`.html` 或 `.txt` 扩展名。
- front matter 是 Markdown 表示层能力，HTML/TXT 不嵌入 YAML front matter。
- PAGE XML / ALTO XML 需要真实页面尺寸与区域坐标；当前上游未稳定提供 bbox，故
  暂不开放对应选项，禁止从 Markdown 伪造坐标。接入结构化 OCR 后再按真实 geometry
  增加标准导出。

## 2. 输入与格式识别

- 支持格式族: `pdf` `docx` `xls` `xlsx` `pptx` `vsdx` `csv` `json` `xml` `zip` `image` `html`。
- **`--type` 手动覆盖的合法取值共 15 个**（clap 白名单）: `pdf` `doc` `docx` `xls`
  `xlsx` `ppt` `pptx` `vsd` `vsdx` `csv` `json` `xml` `zip` `image` `html`。
  其中 `doc` / `ppt` / `vsd` 是旧版二进制格式，**虽为合法 `--type` 取值但解析网关
  实测拒绝**（见下「明确不支持」），会给出明确报错而非静默失败。
- **图像输入支持 6 种格式**：`png` `jpg/jpeg` `gif` `bmp` `tiff` `webp`。
  预处理按 `capability_matrix.toml` 中的模型级能力执行：`paddleocrvl` 历史部署在
  三份公开样本上实测推荐 1280px，1408px 全接受、1536px 起受 2048 Token 上限
  拒绝；2026-10-26 最终复测连续两次 `base_url_missing`，当前跳过并由 qwen36 /
  qwen3-VL 兜底。尚未测出尺寸边界的视觉模型默认保留原图。image crate 启用
  png/jpeg/bmp/gif/tiff/webp 解码，
  data URL 的 MIME 与实际编码一致（gif→image/gif、tiff→image/tiff）。
  图像输入先判「文档 or 照片」（视觉模型），照片按策略跳过。
- 明确不支持: 旧版二进制 `.ppt` `.vsd`，以及 `.doc`（解析网关实测拒绝，
  HTTP 400 `Unsupported file type: doc`，2026-10-18；报错并提示另存为 `.docx`）。
- 识别优先级: 内容魔数 > 容器内部结构（OOXML 条目名 / OLE2 目录流名）> 扩展名兜底；
  `--type` 手动覆盖。OLE2 容器配 OOXML 扩展名时给出"疑似加密文档"警告。
- URL 输入先流式下载（上限 200 MB）再统一识别；识别以字节内容为准。

## 3. 处理档位 (`--mode`)

只有两档，**默认 `rigor`**（2026-10-21 决策：准确率排第一，取消原 `balanced` 档）：

| 档位 | 抽取 | 验证 | 排版 |
|---|---|---|---|
| `rigor`（默认） | 多通道（扫描件三通道，见下） | **级联交叉验证（raw-vs-raw）**：数字覆盖 + 词元包含度 ≥0.85 免模型直判 → 未过段 bge-m3 余弦（段落锚定到来源切片页范围 ±1 页） | **对抗式双模型仲裁**（对手经兜底链挑选：qwen3.6-27b → qwen36 → dsv4）+ **双模型全局复核** + **排版验证** + 仲裁后**润色**（light-check 事实保真）+ §3.2 体裁特化 |
| 表格类 (xlsx/xls) | 本地精确抽取 (calamine 逐格) | 抽取即精确，无从验证 | 仅结构归一 —— **跳过全部改写类阶段**（润色/仲裁对逐格准确的产物只引入风险） |
| `speed` | 单通道 | 硬对账 | 规则清洗（§3.1 契约）+ §3.2 体裁特化 |

- 旧值 `balanced` 兼容接受，**映射到 `rigor`**（其准确率诉求由默认档满足；
  其「无验证」特征与准确率第一的原则相悖，故不保留）。
- `balanced` 移除理由：它介于两档之间——比 rigor 快不了多少（润色占大头），
  却没有准确率保证，徒增选择负担。

- 交叉验证默认阈值 0.55（2026-10-21 极限测试：6 份法律文本中实际被判冲突的段落
  相似度全部落在 0.44~0.69，中位 0.65；旧默认 0.70 恰好切在分布之上，把每一段
  正常同源段落都误判为冲突，单文档耗时暴涨至 666~1132s 且 92% 段落标记
  unverified；降到 0.55 后冲突段从 13 降到 1 量级，真正有分歧的段落仍被捕获）；
- **验证顺序（2026-10-26 重构）**：raw-vs-raw —— 主通道原始段落 vs 第二通道证据
  同代比对，仲裁修正后再润色（润色改写不再制造相似度漂移；润色正确性由
  light-check 承担）。**级联数据最小化**：数字多重集覆盖 + bigram 包含度 ≥0.85
  的段落免模型直判通过，仅未过段触 bge-m3（嵌入模型带兜底链，双侧同模型）；
- **逐页探测路由**：单次 lopdf 加载逐页分类 Text/Scan/Opaque（≥50 字符文本层
  = Text；文本层缺失且含整页图 = Scan；两者皆无 = Opaque）。纯数字件
  `is_ocr=false`（2026-10-26 实测网关 txt 路径可用），含扫描页即 `is_ocr=true`；
  混合文档逐页取证据源（文本层 / 页图 OCR+VL）。逐页门槛取 50 字符而非 200：
  落款页常仅一百余字符（2026-10-26 N078 第 2 页 111 字符，正是落款与日期所在），
  按 200 判会误弃该页而使落款日期失去验证依据；
- **竖向碎片重组**：内容流逐字定位的 PDF（lopdf 抽出 `云\n南\n省...`）在入
  证据前重组为正常文本，否则行级 / 数字串级比对全假阳性；
- **覆盖检查**：验证后核对「文本层有而产物缺」的数字与行，缺口写入 `--report`
  的 warnings（如实报告，不自动补写 —— 补写属内容改写，超出结构归一契约）；
  低于阈值段落交**对抗式双模型仲裁**：dsv4 与 qwen3.6-27b 各自独立裁决
  （保留/修正/不可决），双方一致才定案；一方不可决采纳可决方；一方保留一方修正
  时倾向保留原文（有一票支持即不擅改）。不可决段插
  `<!-- qyzs:unverified (相似度 <n.nn>) -->` 标记。
  令牌开销约为单模型仲裁的 2 倍（准确率优先，接受）。
仲裁结果应用时有**双护栏**：表格行数不得减少（防结构退化）；修正文本不得超过
原段 2 倍长度（防证据块整块越权重写——2026-10-26 N078 实测 2 页函件被替换出
3 份同文）。越栏一律保留原文并告警。

**切片缝修复**（>15 页文档）：合并切片时检测缝两侧——上片末行无终结标点且
下片首行非结构标记 → 段落拼回；上片尾表与下片首表表头相同 → 视为同一跨缝
表格，去重复表头续接。
- 第二通道：PDF 优先用 lopdf 文本层、docx 用本地 OOXML 抽取；文本层过薄（扫描件）
  时 PDF 改走 **OCR 证据通道**：提取页面内嵌整页图（典型扫描件每页一张
  DCTDecode JPEG，lopdf 直接取原始流字节，纯 Rust 零栅格化、零新增依赖），
  逐页送 OCR 角色链（当前 qwen36，paddleocrvl 恢复后优先）与 qwen3-VL（图像理解：逐字+表格逐格+印章/文号/
  页码要素），4 路并发，与主通道 MinerU 构成**三通道**证据，交叉验证对扫描件真实生效
  （实测冲突段数随证据增强单调下降 7→5→4）。
  两条证据通道全败或本地通道无独立第二通道时，诚实降级为仅润色行为并告警
  （告警持久化到 manifest，`--report` 的 warnings 可见）。

### 3.1 speed 档规则清洗契约（行为承诺）

speed 档**只做结构归一，不改写任何内容**（不增删字句、不改写措辞、不做同义替换）。
操作范围仅以下四项：

1. **标题层级相对深度归一**：按各标题级别在文中首次出现顺序重映射为连续层级
   （仅改写 `#` 数量，标题文字逐字保留）；七级以上非法 Markdown 标题与无空格的
   `#tag` 不视为标题。
2. **空白规整**：3 连以上空行折叠为 1 个空行；行尾空白剥离；文件以单个换行收尾。
3. **标题文本去冗余强调标记**：标题整体被 `**`/`__` 包裹时移除标记（标题本身
   已是强调，再套一层是噪声）；单 `*` 不动（可能是正文符号）。
4. **编号层级重建（§3.2）**：按文档体裁重建标题层级；结构缺失时从
   `第X编/分编/章/节/条` **补建标题行**。

5. **硬换行重组（reflow）**：抽取后统一执行（各档位共用，见 reflow 模块）——
   段内行尾无终结标点且次行行首非结构标记的版式换行拼回连续文本
   （`省人力资源社会\n保障厅` → `省人力资源社会保障厅`），围栏/表格整块透传，
   CJK 直拼、拉丁边界补空格。这是空白归一，字符逐字保留。

围栏代码块（``` / ~~~）内一切内容原样透传。不做内容删增、不做措辞改写。
违反本契约视为缺陷。

> 第 3、4 项是体裁特化能力引入后的补充（2026-10-21）。它们**改变结构**：
> 原本是正文行的 `第一条 …` 可能被提升为标题行。这是「结构识别」而非
> 「内容改写」——文字逐字保留，只改变其在 Markdown 中的层级归属。

### 3.2 体裁识别与排版样式转换

转换收尾阶段按文档体裁选择排版策略：

**体裁识别**（`--no-classify` 关闭）——判定顺序：格式直判（xlsx/pptx/vsdx/image
用途唯一，无需看内容）→ 文本规则 → 视觉模型（仅图片需判「文档 or 照片」）。
文本规则按**置信度**分派：

- 强信号直接定案：文号（`〔YYYY〕N号`）、红头文种行、标准强标记
  （`中华人民共和国国家标准`/`ICS`/`DB53/T`）、标准编号骨架（行首编号 + 范围/术语和定义/
  规范性引用文件）、公文条款骨架（第一/二/三条，或两条+附则，附则容「附　则」全角空格）、
  合同双主体 + 约定措辞/签署区。
- 弱信号送**模型仲裁**：仅弱标准标记（`行业标准`/`GB/T ` 等主题词，须配完整标准编号形）、
  单层章节骨架（第一章+第一条）、段落骨架（一、+（一））。弱信号多为「公文+标准附件」
  合订本，规则无法判决，必须由模型裁决。
- 判定路径在 INFO 行明示：`[规则(强信号)]` / `[模型仲裁(规则弱命中X,改判 Y)]` /
  `[规则(弱命中,模型确认)]` / `[模型(规则判不出兜底)]`，可审计。
- `--classify-model <MODEL>` 指定后改为**模型优先**、规则兜底；不指定则规则优先、
  模型仅在弱命中或判不出时介入。
- 实测（273 份带目录标签语料离线审计）：规则准确率 65% → **93%**，叠加弱命中模型
  仲裁 → **97%**。

**排版样式**——按体裁套用不同层级重建规则：

- 标准规范：编 > 分编 > 章 > 节 > 条。
- 公文 / 合同 / 法规：编 > 章 > 节 > 条 与 一、 > （一） > 1. > （1） 双体系，
  **按文中实际出现的体裁压紧排名**（同一「（一）」在通知体裁是二级、在办法体裁位于
  章条之下却更深级，固定映射必然出错）。
- 结构缺失时（现有标题 < 编号行数的一半）从 `第X编/分编/章/节/条` **补建标题**；
  `（一）`/`1.` 属条款内列举，不升级。
- 首个标题若不是编号单元且其后有编号单元，结构整体下移一级（避免「标题与第一章
  同级」的并列误读）。
- **样式信息补充**：DOCX 读 `word/styles.xml` 的 Heading/标题 样式与段落 `w:pStyle`
  （中文文档常用数字 styleId，须经名称解析才不误判；无命名样式回退 `w:outlineLvl`）；
  PDF 解析页面内容流取字号与字重（字体名 + FontDescriptor ForceBold 位）——字号/字重
  在文字编码损坏（非标准 CMap）时依然有效。样式只做**精确文本匹配后的层级校正**，
  不凭空新增标题。
- 标题文本统一移除 `**`/`__` 冗余强调标记（单 `*` 不动，可能是正文符号）。
- 明确**不做**按编号数值重排段落顺序：跨页/跨节边界判定不可靠，误判代价高于收益。

**图片资产**（`--no-assets` 关闭）：

- OOXML 精确抽取 `word|ppt|xl|visio/media` 原图字节；PDF 经 lopdf 抽内嵌图，
  按「像素/页面点」比值剔除整页扫描底图（300dpi A4 ≈4.17，页内插图远低于 2.5 阈值）。
- 输出 `<assets>/<源文件名>/`，Markdown 用相对路径引用，可整体搬移；`--assets-dir`
  自定义位置。输出到 stdout 时无处落盘，不抽附件。
- 引用重写取**严格计数匹配**：引用数与附件数相等才按序映射，不等则一律标记
  `<!-- qyzs:missing-asset ... -->` 并附「图片附件」索引章节——顺序硬配会把 A 图放到
  B 的位置，静默内容错配比缺失更糟。

## 4. 通道与阶段接入状态

| 格式 | 通道 | 状态 |
|---|---|---|
| pdf | 逐页探测路由 is_ocr + 按批切片（15 页/批）+ MinerU 逐片同步抽取 + 切片缝修复合并 | ✅ |
| docx | MinerU 整文件解析 | ✅ |
| xlsx / xls | 本地表格解析 (calamine) → Markdown 表格 | ✅ |
| pptx / vsdx | 本地 OOXML 部件抽取 (zip + XML) | ✅ |
| image | OCR 角色链（qwen36 / paddleocrvl）/ qwen3-VL（`--image-handling` 策略）；先判「文档 or 照片」，照片跳过 | ✅ |
- 图像输入的细粒度控制：`--image-prompt` 自定义 OCR 引导提示词、`--max-dim`
  设置长边请求值（1~8192 由 dispatch 校验）。
- `--max-dim` 同时作用于图像输入和 PDF 扫描页 OCR 证据；它是请求值，最终尺寸仍由
  模型硬限制钳制。模型尺寸能力未知且未指定该参数时保留原图。
- **图像通道双 OCR 引擎并行交叉**（2026-10-21 引擎基准驱动）：网关实测图像方向只有
  paddleocrvl（专用 OCR）与 qwen3-VL（视觉 chat）两个引擎，二者**并行**跑同一张图，
  以字符 bigram Dice 相似度交叉判定（Dice ≥ 0.70 视为两引擎一致，取其一；**分歧时
  采纳 qwen3-VL**）。单一引擎在敌对版式（如网页打印封面）下会灾难性漏字，双引擎交叉
  正是为消除该失效模式。
- **`--image-handling` 取值集**（clap 白名单）: `auto`（默认）| `ocr` | `describe`
  | `both` | `skip`。
- **`--segment-chars` 章节分段目标字符数**：范围 1~100000，**默认 24000**（由
  dispatch 硬校验，越界报用法错误）。
| html | htmd (html5ever) → Markdown；`<script>/<style>` 入口剥离 | ✅ |

- MinerU 解析默认开启 OCR 辅助（与扫描件难点相符，文本层件不受影响）。
- **引擎熔断与角色兜底链**（2026-10-26 引入并重构）：任一模型**连续 3 次真实调用
  失败**即熔断 10 分钟（半开窗口到期放行一次探测，成功即恢复；跳过不计入失败
  计数）。调用一律经角色链派发——OCR 链 `paddleocrvl → qwen36 → qwen3-VL`、
  VL 链 `qwen3-VL → qwen36`、仲裁对手链 `qwen3.6-27b → qwen36 → dsv4`、
  润色/复核链 `用户模型 → dsv4 → qwen3.6-27b → qwen36`、嵌入链
  `bge-m3 → qwen3-embadding-8b`（双侧同模型）。熔断中的候选直接跳过，
  下线模型一次进程内最多被真实探测 3 次，不再反复浪费时延与令牌。
- **运行前模型预检**：每个 markscan 进程在正式批处理前按实际需要检查模型。扫描页
  OCR/VL 使用首张真实页图，嵌入使用一个最小文本，仲裁/复核/润色使用最小提示；
  同一模型同一通道只检查一次。预检失败会立即熔断 10 分钟并选择角色链下一候选，
  不再等正式任务累计 3 次失败。预检请求与正式请求共享 `--concurrency` 上限并参与
  多 Key 轮询。能力矩阵已标记离线的模型直接跳过，由专项探针确认恢复后更新矩阵。
- **超时预算**：转换场景客户端超时取 `max(用户超时, 300s)`（实测扫描件解析存在
  长尾，默认 30s 会误伤）；交互命令不受影响。
- **超长文档行为（2026-10-18 实测修订）**：40 页/10.7MB 文档网关**同步完成**
  （15.9s），2026-10-17 记录的"30 页/10MB 转异步"阈值未复现；实现上不做轮询，
  若网关返回 pending/running 状态将**显式报错**提示减小文档，不悬挂等待。
- 空白页文档 `md_content` 为空属合法任务结果；整体抽取结果为空时 markscan
  显式报错（空白文档/无文本层扫描件），不产出空文件假成功。
- LLM 响应取文统一 `ChatResponse::primary_text`：content 为空回退 reasoning
  （实测 qwen3-VL 非流式会把完整回答放入 reasoning）。
- **规模成本实测注记（2026-10-18）**：40 页/151KB 文本 PDF rigor 全程 1m21s
  （3 批抽取 + 61KB 产物润色，合成文件无字体资源致文本层为空、交叉验证按契约
  降级）；10 页文本 PDF rigor 全程 2m41s 含 9 段仲裁。仲裁段级成本显著，大文档
  rigor 建议配合 `--min-confidence` 调节。
- **i18n**：markscan 运行时状态/进度/告警消息全量走目录（`msg!`/`msgf!`，
  `{0}` 序号占位符填充）；错误详情携带动态数据以中文为主；帮助文本中文为主。

## 5. 过程数据生命周期

- 工作区: `<缓存基目录>/markscan/<输入 sha256 前 16 位>/`（`--work-dir` 可指定工作区根目录）（缓存基目录与配置
  同约定: XDG_CACHE_HOME > HOME/.cache > APPDATA）。
- manifest.json 记录输入指纹与 段×阶段 状态机；切片二进制在对应段完成后立即
  流式删除（磁盘大头先走）。
- **成功**：删除整个工作目录（`--no-clean` 保留全部产物）。
- **失败**：保留现场，错误信息附工作区路径与续跑提示。
- `--resume`：显式续跑；输入指纹一致时跳过已完成段（幂等）。**默认重跑即重新
  处理**——交叉验证工具静默返回历史结果不可接受。
- 并发互斥：同输入活动锁（lock 文件）阻止第二个进程；锁随进程收尾释放。
- 时机性清扫：启动时删除 mtime 超 7 天且无锁文件的残留工作目录。

## 6. 退出码契约

外部脚本按退出码区分失败类型（`src/error.rs` 的 `exit_code`）：

| 退出码 | 含义 | 触发 |
|---|---|---|
| 0 | 成功 | 含 `Skipped`（判定为真实照片而跳过，非失败） |
| 2 | 用法错误 | 参数非法、格式不支持、输入不存在 |
| 3 | 凭据错误 | 缺少/无效 API Key |
| 4 | 超时 | 网关请求超时 |
| 5 | IO / PDF 错误 | 文件读写、PDF 解析失败 |
| 69 | 服务不可达 | 网络连接失败（`EX_UNAVAILABLE`） |
| 70 | 服务端错误 | 网关 5xx、响应解析失败（`EX_SOFTWARE`） |
| 78 | 配置错误 | 配置文件格式/键值非法（`EX_CONFIG`） |

批量模式（多文件/目录输入）中，单个文件失败即中止整批并返回上述退出码；
`Skipped` 不计为失败，继续处理后续文件。

## 7. dry-run

`--dry-run` 完全离线（URL 输入除外），不消耗任何网关模型调用，输出: 识别格式与
依据、页数/切片批数、档位阶段序列、规模警告、输出目标；`--format json` 输出机器
可读规划。
