# QYZS SCAN — 智能文档转 Markdown 流水线 (SSOT)

本文档是 `qyzs scan` 子命令行为契约的唯一事实源。
能力边界实测数据见 `capability_matrix.toml`；发布制度见 `docs/RELEASE.md`。

## 1. 定位

一站式文档转 Markdown：输入本地文件或 http(s) URL，自动识别格式、路由抽取
通道、可选多轮交叉验证与 LLM 排版润色，输出结构忠实、层级正确的 Markdown。

## 2. 输入与格式识别

- 支持格式族: `pdf` `docx` `xls` `xlsx` `pptx` `vsdx` `image`
  (png/jpg/gif/bmp/tiff/webp) `html`。
- 明确不支持: 旧版二进制 `.ppt` `.vsd`，以及 `.doc`（解析网关实测拒绝，
  HTTP 400 `Unsupported file type: doc`，2026-10-18；报错并提示另存为 `.docx`）。
- 识别优先级: 内容魔数 > 容器内部结构（OOXML 条目名 / OLE2 目录流名）> 扩展名兜底；
  `--type` 手动覆盖。OLE2 容器配 OOXML 扩展名时给出"疑似加密文档"警告。
- URL 输入先流式下载（上限 200 MB）再统一识别；识别以字节内容为准。

## 3. 处理档位 (`--mode`)

| 档位 | 抽取 | 验证 | 排版 |
|---|---|---|---|
| `speed` | 单通道 | 硬对账 | 规则清洗（§3.1 契约）+ §3.2 体裁特化 |
| `balanced` | 单通道 | light-check（质检不过回退原文） | dsv4 单轮润色（专名表约束）+ §3.2 体裁特化 |
| `rigor` | 多通道（扫描件三通道，见下） | bge-m3 段落相似度 + light-check | dsv4 逐段仲裁（≤2 轮）+ 润色 + 全局审查（仅报告）+ §3.2 体裁特化 |

- 交叉验证默认阈值 0.70（2026-10-18 实测：正确段落对 lopdf 文本层证据的相似度
  0.57~0.75，0.85 会把大量正确段落送入仲裁造成无谓开销）；
  低于阈值段落交 dsv4 仲裁，不可决段插 `<!-- qyzs:unverified -->` 标记。
- 第二通道：PDF 优先用 lopdf 文本层、docx 用本地 OOXML 抽取；文本层过薄（扫描件）
  时 PDF 改走 **OCR 证据通道**：提取页面内嵌整页图（典型扫描件每页一张
  DCTDecode JPEG，lopdf 直接取原始流字节，纯 Rust 零栅格化、零新增依赖），
  逐页送 paddleocrvl（文字转录）与 qwen3-VL（图像理解：逐字+表格逐格+印章/文号/
  页码要素），4 路并发，与主通道 MinerU 构成**三通道**证据，交叉验证对扫描件真实生效
  （实测冲突段数随证据增强单调下降 7→5→4）。
  两条证据通道全败或本地通道无独立第二通道时，诚实降级为 balanced 行为并告警
  （告警持久化到 manifest，`--report` 的 warnings 可见）。

### 3.1 speed 档规则清洗契约（行为承诺）

规则清洗**只做结构归一，不改写任何内容**。操作范围仅有两项：

1. **标题层级相对深度归一**：按各标题级别在文中首次出现顺序重映射为连续层级
   （仅改写 `#` 数量，标题文字逐字保留）；七级以上非法 Markdown 标题与无空格的
   `#tag` 不视为标题。
2. **空白规整**：3 连以上空行折叠为 1 个空行；行尾空白剥离；文件以单个换行收尾。

围栏代码块（``` / ~~~）内一切内容原样透传。不做同义词改写、不做内容删增、
不做格式重排之外的任何变换。违反本契约视为缺陷。

### 3.2 体裁识别与排版样式转换

转换收尾阶段按文档体裁选择排版策略：

**体裁识别**（`--no-classify` 关闭）——判定顺序：格式直判（xlsx/pptx/vsdx/image
用途唯一，无需看内容）→ 文本规则 → 视觉模型（仅图片需判「文档 or 照片」）。
文本规则按**置信度**分派：

- 强信号直接定案：文号（`〔YYYY〕N号`）、红头文种行、标准强标记
  （`中华人民共和国国家标准`/`ICS`/`DB53/T`）、标准编号骨架（行首编号 + 范围/术语和定义/
  规范性引用文件）、公文条款骨架（第一/二/三条，或两条+附则，附则容「附　则」全角空格）、
  合同双主体 + 约定措辞/签署区。
- 弱信号送**模型仲裁**：仅弱标准标记（`行业标准`/`GB/T ` 等主题词，须配完整标准编号形）、
  单层章节骨架（第一章+第一条）、段落骨架（一、+（一））。弱信号多为「公文+标准附件」
  合订本，规则无法判决，必须由模型裁决。
- 判定路径在 INFO 行明示：`[规则(强信号)]` / `[模型仲裁(规则弱命中X,改判 Y)]` /
  `[规则(弱命中,模型确认)]` / `[模型(规则判不出兜底)]`，可审计。
- `--classify-model <MODEL>` 指定后改为**模型优先**、规则兜底；不指定则规则优先、
  模型仅在弱命中或判不出时介入。
- 实测（273 份带目录标签语料离线审计）：规则准确率 65% → **93%**，叠加弱命中模型
  仲裁 → **97%**。

**排版样式**——按体裁套用不同层级重建规则：

- 标准规范：编 > 分编 > 章 > 节 > 条。
- 公文 / 合同 / 法规：编 > 章 > 节 > 条 与 一、 > （一） > 1. > （1） 双体系，
  **按文中实际出现的体裁压紧排名**（同一「（一）」在通知体裁是二级、在办法体裁位于
  章条之下却更深级，固定映射必然出错）。
- 结构缺失时（现有标题 < 编号行数的一半）从 `第X编/分编/章/节/条` **补建标题**；
  `（一）`/`1.` 属条款内列举，不升级。
- 首个标题若不是编号单元且其后有编号单元，结构整体下移一级（避免「标题与第一章
  同级」的并列误读）。
- **样式信息补充**：DOCX 读 `word/styles.xml` 的 Heading/标题 样式与段落 `w:pStyle`
  （中文文档常用数字 styleId，须经名称解析才不误判；无命名样式回退 `w:outlineLvl`）；
  PDF 解析页面内容流取字号与字重（字体名 + FontDescriptor ForceBold 位）——字号/字重
  在文字编码损坏（非标准 CMap）时依然有效。样式只做**精确文本匹配后的层级校正**，
  不凭空新增标题。
- 标题文本统一移除 `**`/`__` 冗余强调标记（单 `*` 不动，可能是正文符号）。
- 明确**不做**按编号数值重排段落顺序：跨页/跨节边界判定不可靠，误判代价高于收益。

**图片资产**（`--no-assets` 关闭）：

- OOXML 精确抽取 `word|ppt|xl|visio/media` 原图字节；PDF 经 lopdf 抽内嵌图，
  按「像素/页面点」比值剔除整页扫描底图（300dpi A4 ≈4.17，页内插图远低于 2.5 阈值）。
- 输出 `<assets>/<源文件名>/`，Markdown 用相对路径引用，可整体搬移；`--assets-dir`
  自定义位置。输出到 stdout 时无处落盘，不抽附件。
- 引用重写取**严格计数匹配**：引用数与附件数相等才按序映射，不等则一律标记
  `<!-- qyzs:missing-asset ... -->` 并附「图片附件」索引章节——顺序硬配会把 A 图放到
  B 的位置，静默内容错配比缺失更糟。

## 4. 通道与阶段接入状态

| 格式 | 通道 | 状态 |
|---|---|---|
| pdf | 本地按批切片（15 页/批）+ MinerU 逐片同步抽取 + 合并 | ✅ |
| docx | MinerU 整文件解析 | ✅ |
| xlsx / xls | 本地表格解析 (calamine) → Markdown 表格 | ✅ |
| pptx / vsdx | 本地 OOXML 部件抽取 (zip + XML) | ✅ |
| image | paddleocrvl / qwen3-VL（`--image-handling` 策略）；先判「文档 or 照片」，照片跳过 | ✅ |
| html | htmd (html5ever) → Markdown；`<script>/<style>` 入口剥离 | ✅ |

- MinerU 解析默认开启 OCR 辅助（与扫描件难点相符，文本层件不受影响）。
- **超时预算**：转换场景客户端超时取 `max(用户超时, 300s)`（实测扫描件解析存在
  长尾，默认 60s 会误伤）；交互命令不受影响。
- **超长文档行为（2026-10-18 实测修订）**：40 页/10.7MB 文档网关**同步完成**
  （15.9s），2026-10-17 记录的"30 页/10MB 转异步"阈值未复现；实现上不做轮询，
  若网关返回 pending/running 状态将**显式报错**提示减小文档，不悬挂等待。
- 空白页文档 `md_content` 为空属合法任务结果；整体抽取结果为空时 scan
  显式报错（空白文档/无文本层扫描件），不产出空文件假成功。
- LLM 响应取文统一 `ChatResponse::primary_text`：content 为空回退 reasoning
  （实测 qwen3-VL 非流式会把完整回答放入 reasoning）。
- **规模成本实测注记（2026-10-18）**：40 页/151KB 文本 PDF rigor 全程 1m21s
  （3 批抽取 + 61KB 产物润色，合成文件无字体资源致文本层为空、交叉验证按契约
  降级）；10 页文本 PDF rigor 全程 2m41s 含 9 段仲裁。仲裁段级成本显著，大文档
  rigor 建议配合 `--min-confidence` 调节。
- **i18n**：scan 运行时状态/进度/告警消息全量走目录（`msg!`/`msgf!`，
  `{0}` 序号占位符填充）；错误详情携带动态数据以中文为主；帮助文本中文为主。

## 5. 过程数据生命周期

- 工作区: `<缓存基目录>/scan/<输入 sha256 前 16 位>/`（`--work-dir` 可指定工作区根目录）（缓存基目录与配置
  同约定: XDG_CACHE_HOME > HOME/.cache > APPDATA）。
- manifest.json 记录输入指纹与 段×阶段 状态机；切片二进制在对应段完成后立即
  流式删除（磁盘大头先走）。
- **成功**：删除整个工作目录（`--no-clean` 保留全部产物）。
- **失败**：保留现场，错误信息附工作区路径与续跑提示。
- `--resume`：显式续跑；输入指纹一致时跳过已完成段（幂等）。**默认重跑即重新
  处理**——交叉验证工具静默返回历史结果不可接受。
- 并发互斥：同输入活动锁（lock 文件）阻止第二个进程；锁随进程收尾释放。
- 时机性清扫：启动时删除 mtime 超 7 天且无锁文件的残留工作目录。

## 6. dry-run

`--dry-run` 完全离线（URL 输入除外），不消耗任何网关模型调用，输出: 识别格式与
依据、页数/切片批数、档位阶段序列、规模警告、输出目标；`--format json` 输出机器
可读规划。
