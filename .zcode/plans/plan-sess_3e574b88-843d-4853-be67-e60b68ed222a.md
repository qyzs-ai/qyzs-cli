## 修复方案 (P0 缺边界 + P1 clap 互斥)

### 修改/新增文件

1. **新增** `src/cli/validate.rs` (~70 行)
   - `pub(crate) fn validate_chat_temperature(t: Option<f64>) -> QyzsResult<()>`,范围 `[0.0, 2.0]`,拒 NaN/±∞
   - `pub(crate) fn validate_chat_top_p(p: Option<f64>) -> QyzsResult<()>`,范围 `[0.0, 1.0]`,拒 NaN/±∞
   - `pub(crate) fn validate_chat_max_tokens(m: Option<u32>) -> QyzsResult<()>`,仅下界 `>= 1` (上界由网关决定,不替网关拍上限)
   - `pub(crate) fn validate_sam_threshold(t: Option<f64>) -> QyzsResult<()>`,范围 `[0.0, 1.0]`,拒 NaN/±∞
   - `pub(crate) fn validate_usage_kind(k: Option<&str>) -> QyzsResult<()>`,白名单 `[chat, ocr, asr, embed, rerank]`
   - 全部错误以 `QyzsError::Usage` 返回,与现有 `dispatch.rs:140-148` 的 `min_confidence` 同款
   - `#[cfg(test)] mod tests` — 每个校验函数覆盖 None / 下界 / 上界 / 非法上值 / 非法负值 / NaN / Infinity

2. **修改** `src/cli/mod.rs` — 注册 `pub mod validate;`

3. **修改** `src/cli/dispatch.rs`
   - `Commands::Chat { ... } =>`: 分支首行依次 `validate::validate_chat_temperature(temperature)?` / `validate_chat_top_p(top_p)?` / `validate_chat_max_tokens(max_tokens)?`
   - `Commands::Sam { ... } =>`: 分支首行 `validate::validate_sam_threshold(threshold)?`
   - `Commands::Usage { ... } =>`: 分支首行 `validate::validate_usage_kind(kind.as_deref())?`

4. **修改** `src/cli/args.rs`
   - `--top-p` help 从 `"Top-P 核采样概率"` → `"Top-P 核采样概率 (0.0~1.0)"`
   - `--max-tokens` help 从 `"最大生成 Token 数量"` → `"最大生成 Token 数量 (≥ 1)"`
   - `--pages` 加 `conflicts_with = "chunk_size"`
   - `--chunk-size` 加 `conflicts_with = "pages"`
   - `--clear` 加 `conflicts_with_all = ["days", "model", "kind", "key"]` (`--clear --json` / `--clear --hourly` 不冲突 — `--clear` 在 handler 里先返回,后两个是输出呈现开关,不需互斥)

5. **修改** `tests/integration_tests.rs`
   - `test_pdf_split_pages_chunksize_conflict`: `Cli::try_parse_from(["qyzs", "pdf-split", "a.pdf", "--pages", "1-3", "--chunk-size", "5"])` → `is_err()`
   - `test_usage_clear_conflicts_filters`: `--clear --days 7` / `--clear --model dsv4` / `--clear --kind chat` / `--clear --key xxx` 各自 `is_err()`;`--clear --json` 与 `--clear --hourly` 仍 `is_ok()`

### 风格对齐

- 错误文案与 `dispatch.rs:140-148` 同款:`--<flag> 取值必须在 <min>~<max> 之间，当前: {val}` (NaN/Infinity 走 `f64` Display)
- `validate_*` 用 `pub(crate)` 与 `resolver.rs` 现有 `validate_base_url` / `parse_color_choice` 风格一致
- 测试 mod 放 `validate.rs` 内部 `#[cfg(test)] mod tests`,与 `detect.rs::tests`、`mod.rs::tests` 同款

### 风险与回归评估

| 改 | 文件 | 风险 | 测试位置 |
|---|---|---|---|
| chat temperature/top-p/max-tokens 校验 | dispatch.rs + validate.rs | 低 — 现有集成/网关测试不调这些参数,不会回归 | validate.rs 单测 |
| sam threshold 校验 | dispatch.rs + validate.rs | 低 — 同上 | 单测 |
| usage --kind 校验 | dispatch.rs + validate.rs | 低 — 台账只用上述 5 个 kind,无回归风险 | 单测 |
| pdf-split `conflicts_with` | args.rs | 低 — clap 内置行为,集成测试覆盖 | integration_tests |
| usage --clear `conflicts_with_all` | args.rs | 低 — `--clear` 在 handler 先返回,加冲突不会改变现有路径 | integration_tests |
| 帮助文本 | args.rs | 无 — 仅扩展文字 | — |
